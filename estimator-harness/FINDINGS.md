# Findings from the first harness run

Parameter set analysed: the TriFHE instance as written in the draft
memorandum — \(N = 2187 = 3^7\), \(q = 34993\), dense ternary secret.

Generated by `trifhe_estimator.run_estimate`. The machine-readable records are in
`records/`; they carry the estimator commit, Sage version, cost models, and every
modelling assumption. This file is the human summary.

## Headline

**No bit-security figure from this parameter set is quotable.** Three
blocker-severity findings fire before the estimator is even reached, and the
estimator's own output for the literal reading is saturated against its
block-size bound rather than converged.

## Blockers found without the estimator

### 1. \(q = 34993\) is composite

\(34993 = 7 \times 4999\). If the specification calls this a prime modulus, that
statement is false. Consequences:

- \(\mathbb{Z}_q\) is not a field. It has zero divisors, and not every nonzero
  element is invertible — which matters wherever the scheme inverts a ciphertext
  component or a scaling factor.
- The NTT correctness argument built on primality does not hold.

### 2. The NTT congruence is a false positive

The specification's check \(q \equiv 1 \pmod{2N}\) does pass:
\(34993 = 8 \times 4374 + 1\), so \(q \equiv 1 \pmod{4374}\). But that congruence
holding for the *product* is not what an NTT needs. A negative-wrapped
convolution NTT requires a primitive \(2N\)-th root of unity, which exists in
\(\mathbb{Z}_p\) only when \(p \equiv 1 \pmod{2N}\), and over a composite modulus
**each CRT component must satisfy this independently**. Neither does:

| component | residue mod 4374 | satisfies \(\equiv 1\)? |
| --- | --- | --- |
| 7 | 7 | no |
| 4999 | 625 | no |

So the product congruence is satisfied while no factor is. The NWC NTT cannot be
constructed as specified. This is the kind of check that looks green on a slide
and is red in the implementation.

### 3. \(x^{2187} + 1\) is not a cyclotomic polynomial

For odd \(d\), \(x^d + 1\) is divisible by \(x + 1\). So
\(\mathbb{Z}[x]/(x^{2187} + 1)\) is not a field extension and carries zero
divisors. The 3-power cyclotomic of comparable size is \(\Phi_{2187}\), whose
degree is
\[\varphi(3^7) = 3^7 - 3^6 = 2 \cdot 3^6 = 1458,\]
not 2187. Writing "\(N = 2187\)" for a power-of-3 ring is therefore ambiguous by
729 dimensions, and the harness ships both readings as separate presets so the
gap is visible rather than assumed away.

### 4. There is no noise budget

\(\log_2 q \approx 15.09\). Against an error standard deviation of 3.19 that
leaves roughly 13.4 bits of total headroom — less than a single homomorphic
multiplication plus relinearisation consumes in a BGV/BFV-style scheme.

This is the finding most likely to be misread as good news. **A smaller \(q\)
makes the lattice harder and the scheme less useful.** The very large bit counts
below are a direct consequence of the modulus being far too small to compute
with, so the security number and the noise budget must always be reported
together. As specified, this is not a working FHE parameter set.

## Estimator output

Cheapest attack in every cost model and both readings: **`dual_hybrid`**.
`usvp` returns infinite cost, i.e. it was pruned by the block-size bound, not
that it is impossible.

### Literal reading — \(n = 2187\), \(\mathbb{Z}[x]/(x^{2187}+1)\)

| cost model | security | cheapest attack |
| --- | --- | --- |
| MATZOV (estimator default) | \(\ge 499.0\) bits | dual_hybrid, \(\beta = 1662\) |
| core-SVP classical | \(\ge 484.5\) bits | dual_hybrid |
| core-SVP quantum | \(\ge 443.7\) bits | dual_hybrid, \(\beta = 1673\) |
| core-SVP paranoid | \(\ge 356.3\) bits | dual_hybrid, \(\beta = 1715\) |

Every row is **saturated**: the optimal \(\beta\) sits within 10% of the
estimator's `max_beta = 1754` bound. These are lower bounds imposed by the search
range, not converged optima, which is why they are written \(\ge\). `bdd` and
`bdd_hybrid` both report \(\beta = 1754\) exactly — pinned at the cap.

### Cyclotomic reading — \(n = 1458\), \(\mathbb{Z}[x]/\Phi_{2187}(x)\)

| cost model | security | cheapest attack |
| --- | --- | --- |
| MATZOV | 325.7 bits | dual_hybrid |
| core-SVP classical | 306.9 bits | dual_hybrid |
| core-SVP quantum | 280.6 bits | dual_hybrid |
| core-SVP paranoid | 226.5 bits | dual_hybrid |

These converge — they are not saturated — so this reading produces figures of the
right shape to defend. The ~100-bit spread between MATZOV and core-SVP paranoid
is the honest error bar, and it is the reason a single number from a single cost
model does not survive review.

## The keyspace gap, quantified

| quantity | value |
| --- | --- |
| raw dense-ternary keyspace, \(n = 2187\) | \(3^{2187} \approx 2^{3466}\) |
| raw dense-ternary keyspace, \(n = 1458\) | \(\approx 2^{2311}\) |
| actual security, \(n = 1458\), core-SVP quantum | \(\approx 2^{281}\) |

The keyspace figure overstates the defensible security level by more than a
factor of eight in the exponent. This is exactly why keyspace must never appear
as a security claim: \(2^{3466}\) and \(\ge 2^{444}\) are both "very large", but
only one of them is a cryptanalytic statement, and an auditor will ask which
attack the first number resists. The answer is exhaustive search, which is not
the relevant attack.

## What this matrix does not cover

The estimator models plain LWE. It says nothing about:

- **Meet-LWE** ([May, CRYPTO 2021](https://eprint.iacr.org/2021/216)) —
  representation-technique MitM tuned to small and sparse secrets. Not
  implemented in the estimator, and a dense ternary secret is squarely in scope.
- **Cool and Cruel** ([arXiv:2403.10328](https://arxiv.org/abs/2403.10328)) —
  statistical dual attack exploiting uneven secret-coordinate contribution,
  reported to beat estimator dual costs for small secrets. Since `dual_hybrid` is
  already the cheapest attack here, this is the most likely source of a further
  reduction.
- **Subfield / structural attacks**
  ([Elias–Lauter–Ozman–Stange](https://eprint.iacr.org/2015/106)) — entirely
  outside the plain-LWE model, and directly relevant given blocker 3. A ring that
  is not a field extension has no protection from the "no known ring attack"
  assumption the plain-LWE reduction relies on.
- **IND-CPA\(^D\)** ([Li–Micciancio](https://eprint.iacr.org/2020/1533)) — a
  scheme can be 300-bit lattice-hard and still fully broken by
  decryption-failure key recovery. Orthogonal to everything above.

## Recommended next steps

1. **Fix the modulus.** Pick a prime \(q\) with \(q \equiv 1 \pmod{2N}\) for the
   actual \(N\), or specify an explicit RNS chain where every component satisfies
   it. Until then the NTT is unimplementable as written.
2. **Fix the ring.** State whether the intended ring is \(\Phi_{3^k}\) (dimension
   \(2 \cdot 3^{k-1}\)) or a power-of-two cyclotomic. Both are sound;
   \(x^{3^k} + 1\) is not.
3. **Raise \(q\) to a realistic FHE size** and re-run. Security will drop sharply
   — expect the figure to move from the 300–500 range toward the 128–192 range,
   which is where a defensible parameter set actually lives.
4. **Specify the error distribution.** The current record carries
   \(\sigma = 3.19\) as an *assumption* borrowed from the HE Standard. Every
   number above is void if the implementation differs.
5. **Cost Meet-LWE and Cool-and-Cruel separately.** The estimator will not do it,
   and `dual_hybrid` dominating means these are the attacks most likely to move
   the headline.
6. **Delete the keyspace and RSA-qubit-scaling claims** from all documents. Both
   are non-cryptanalytic and both will be challenged in the first review pass.
